# 《悬浮时钟》开发计划与里程碑

> 版本：v1.0 ｜ 日期：2026-10-02 ｜ 状态：待确认
> 前置：文档与原型（本次交付）→ 用户确认 → 进入开发

## 里程碑总览（建议 8 周，单人全栈节奏；两人并行可压缩至 5 周）

| 周次 | 里程碑 | 关键产出 | 出口条件 |
| --- | --- | --- | --- |
| W1 | **Spike 验证周** | ① 鸿蒙悬浮窗最小 Demo（TYPE_FLOAT + 拖动 + 权限流）② 鸿蒙后台保活实测报告（Spike-1 四项矩阵）③ Android 悬浮窗最小 Demo（FGS + overlay）④ 双端工程脚手架 + 设计 token 落地 | 鸿蒙版 Go/No-Go 数据齐备，产品承诺文案定稿 |
| W2–W3 | **Android MVP** | 计时引擎 + 悬浮窗三模式 + 倒计时闹钟兜底 + 权限引导（含 5 厂商配置）+ 首页/样式/设置 | PRD §9 验收 1–4 在小米/OPPO 真机通过 |
| W4–W5 | **鸿蒙 MVP** | 同等功能集 + reminderAgent 兜底 + 鸿蒙权限引导 | 鸿蒙真机通过同等验收 |
| W6 | **平台特色 + 打磨** | Android 小组件、鸿蒙服务卡片、（若拍板 Q5）实况窗；动画/样式细化；功耗实测调优 | 功耗指标达标（PRD §7） |
| W7 | **内测** | 双端测试分发（Android 蒲公英/官网；鸿蒙 AGC 开放测试）≥ 30 名种子用户 | 崩溃率 < 0.3%，悬浮窗开启率 > 70% |
| W8 | **提审上线** | 商店素材、隐私政策页、软著/开发者资质、提审与整改 | 5 安卓商店 + AppGallery 过审 |

## 团队配置建议

- 最小：1 名全栈（Android + 鸿蒙均熟）+ 设计复用本次原型
- 理想：Android 1 + 鸿蒙 1 并行（W2 起双线，总周期 ~5 周）

## 关键依赖与前置事项（开发启动前需准备）

1. 鸿蒙：个人/企业开发者账号 + AppGallery 开发者资质（实名，审核约 1–3 天，提前办）
2. Android：各商店开发者账号（小米/OV/荣耀/应用宝，软著可后补但建议尽早申请）
3. 产品名与图标定稿（PRD Q1）
4. 隐私政策托管页（无个人数据收集也要有，商店审核必备）

## 变更管理

- 每周周五里程碑评审，风险登记册（技术方案 §7）随评审更新
- 鸿蒙 Spike 若结论为"退后台 N 分钟后停更且无合规手段"：产品承诺调整为「前台/亮屏悬浮 + 到点必达」，其余范围不变，不阻塞 Android 线
